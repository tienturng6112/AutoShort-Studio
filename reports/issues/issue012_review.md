## 3. Preview vs. Pipeline Code Paths

Preview and final pipeline rendering utilize two distinct code paths:

### 3.1 Preview Code Path
- **UI Invocation**: `SettingsDialog.preview_voice(self, speaker, combo, button)` in `desktop_app.py:L362`.
- **Worker Thread**: `PreviewWorker(QThread)` in `desktop_app.py:L80`.
- **Adapter call**: `EdgeTTSProvider.preview(self, text, voice_name)` in `edge_tts_provider.py:L78`.
- **Method implementation**: Synthesizes MP3 byte streams directly in-memory using `edge_tts.Communicate` without writing to a local cached segments folder.

### 3.2 final Pipeline Code Path
- **Pipeline entry**: `PipelineRunner` calls `VoiceService.synthesize_transcript` in `run_pipeline.py:L413`.
- **Adapter call**: `EdgeTTSProvider.generate(self, text, voice_name, output_path)` in `edge_tts_provider.py:L34`.
- **Method implementation**: Downloads separate WAV segments to the project `tts/` directory, extracts timing-aligned word boundaries, and mixes the clips onto a unified audio canvas matching the video duration.

## 4. Root Cause Analysis of Observed Bugs

### Bug 1: Selecting Hoài My previews an English sentence
* **Mechanism**: In `preview_voice`, language check uses a prefix starts-with check:
  ```python
  if voice_name.startswith("vi-"):
  ```
* **Root Cause**: On systems or package versions where `edge-tts` returns full description names (e.g. starting with `"Microsoft Server Speech..."` or `"Microsoft..."` instead of the pure ID `vi-VN-HoaiMyNeural`), `startswith("vi-")` returns `False`. The code falls back to the English preview text.
* **Resolution suggestion**: Change the check to check substring containment case-insensitively:
  ```python
  if "vi-" in voice_name.lower():
  ```

### Bug 2: Selecting Nam Minh plays Hoài My's voice
* **Mechanism**: In `on_preview_finished`, previews are written to a static file path:
  ```python
  temp_path = os.path.abspath("projects/temp_preview/temp_preview.mp3")
  ```
* **Root Cause**: When the user previews a different voice back-to-back:
  1. The `QMediaPlayer` keeps a file lock or a cached stream buffer of the previously played `temp_preview.mp3` (Hoài My).
  2. Writing the new audio data (Nam Minh) to the same path is blocked by the OS file lock or the newly generated byte array is ignored because `QMediaPlayer` plays from its internal cache/buffer.
* **Resolution suggestion**: Synthesize unique file paths per speaker/voice, and release the player source before overwriting:
  ```python
  temp_path = os.path.abspath(f"projects/temp_preview/temp_preview_{voice_name}.mp3")
  ```
